# Plan review: Claude Code look and feel (status line redesign + `look` band mod), review 2
Verdict: PASS WITH CHANGES
Summary: Review 1 is mostly resolved, and the spike backs up the core event path. There are no blockers. Five problems need fixing before handoff:
- The API refuses `$.state` writes inside the `ui.render` hook, which is where the plan detects task ends.
- Dedupe does not survive `--resume`/`cz --continue`.
- Cross-session `$.store` sharing and the shared CI cache are unverified and not keyed by repo.
- The ✕ click has no keyboard path in zellij.
- No one has checked that a failed background shell actually reports `failed`.

Review-1 status:

- Resolved with residue: 3 (contradictory text), 6 (store concurrency), 7 (poll interval mismatch), 8 (the "ASCII fallback" is promised but not in the rules), 13 (CI needs nodejs/npm).
- Not resolved: 2 (the width numbers are wrong).
- Partly resolved: 16 (label granularity).

## Unnamed risks
- Notification rows are re-rendered for many reasons (scroll `onScreen` changes, width changes, ctrl+o, switching the agent view), so the render hook fires repeatedly for one task. Likelihood: high. Mitigation: findings 1 and 2. Ingestion must be idempotent and keyed to known running items.
- The pinned CI version drifts from the locally auto-updated one, so CI passes against an API the user no longer runs. Likelihood: high (it already happened once). Mitigation: a version warning in the wrapper, upstream-watch, and a "last verified on" line in docs/look.md.
- The `require-check` Stop hook runs `make check` (300 s timeout) on every Stop. Adding `claude plugin test` adds seconds to each turn end. Likelihood: medium. Mitigation: measure it, and keep the mod tests fast or cache by input hash (require-check already caches).
- A store write failing (4 MiB cap, JSON error) inside a timer would kill the interval silently ("a refused period ends the interval"). Likelihood: low. Mitigation: try/catch inside every timer callback, and log once.
- Eighth-block partial glyphs and the dim track may render with a visible seam or a wrong cell width in zellij. The spike checked the band's Nerd Font set A only, not `▉▊▋▌▍▎▏` in the status line. Likelihood: low. Mitigation: a 30-second visual check in zellij during the status line task.

## Questions for the user (max 5)
1. Do you run Claude Code in its fullscreen layout inside zellij (mouse clicks reach it), or in main-screen mode? Why it matters: ✕ and toast clicks only work where clicks are reported, and demo priority 3 uses ✕. Recommendation: add hotkeys either way, and keep `/band clear` as the guaranteed path.
2. When you or Claude deliberately stop an agent or background shell (`killed`), should it show as a red failure? Why it matters: right now a stopped agent pins red until you dismiss it. Recommendation: no. Show `killed` as a dim, neutral end.
3. In narrow zellij splits, what should go first when the status line does not fit: the bars (keep the percentages), the 7d meter, or the repo name? Why it matters: the worst-case line is about 105 columns against a target of 70+. Recommendation: drop the bars first, then shorten the branch, and keep all three percentages.
4. After `cz --continue`, should alerts from the previous session (a failed agent) come back? Why it matters: the fix for finding 2 drops them, and CI and backup alerts come back on their own from polling. Recommendation: no. Only CI and backup survive a resume, because they are re-derived from live sources.
