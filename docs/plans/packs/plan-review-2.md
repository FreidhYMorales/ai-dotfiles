# Plan review: opt-in packs (`ai-pack` + `pack-hint`), review 2
Verdict: PASS WITH CHANGES
Summary: Review 1 is mostly fixed. 13 of 17 findings are fully resolved. 4 are only partly resolved (#3 npm pinning, #6 hook "read-only", #11 exclude cleanup, #12 Chromium env), and two of review 1's risks (Archify update check, CBM version lock) were dropped. There are three new major problems, each checked on this machine or in this repo. `npm install -g` needs root here (npm prefix is `/usr`). The hook runs from the plugin cache, so it cannot read `packs/packs.json`. `make check` would lint third-party shell scripts once they are vendored. No blockers. The estimates are about 25% low, but there is no deadline, so the scope fits.

## Unnamed risks
- Vendored taste-skill scripts may depend on paths or files elsewhere in its repo (it "runs its scripts with Node 22+" and a real browser), so copying only `skills/taste-skill` could break it — medium — in the early manual check, run the vendored copy from a project's `.claude/skills` before committing to vendoring.
- The hook timeout of 2 s on a cache miss in a very large monorepo (`git ls-files` on 500k+ files) times out; Claude may show a hook error instead of silence — low — use `timeout 1.5 git ls-files` inside the script and stay silent on timeout.
- A project that is moved or deleted keeps its refcount, so a machine tool never shows "installed, unused" and is never purged — medium (prune is LATER) — `list` drops projects whose root no longer exists, without writing state.
- Claude Code may key local MCP by the non-realpath cwd (a symlinked path), while ai-pack keys by realpath, so `list` says active but Claude does not load it — low/medium — the manual check covers the subdirectory case; add the symlinked-path case too.
- The CBM watcher and auto-index write to `~/.cache/codebase-memory-mcp` for every project that has the MCP, and with `persistence: true` also to `.codebase-memory/` in the project — low — leave `persistence` at its default and list the cache as a leftover on purge.

## Questions for the user (max 5)
1. Should `remove --purge <tool>` run while other projects still use the tool? — It decides whether one project can break another (finding 9). — Recommendation: refuse, list the other projects, allow `--force`.
2. Should Archify's daily update check and taste-skill's image search (both network calls at run time) be off by default in packs? — "Reviewed and pinned" vs features. — Recommendation: disable Archify's check via env; keep taste's image search and document it.
3. When the manifest bumps a machine-wide tool (playwright-cli, CBM), is it OK that `ai-pack add` in one project upgrades it for every project? — Per-project version isolation is not possible for global installs. — Recommendation: yes, upgrade for all; `list` flags it everywhere and `add` prints "restart all Claude sessions".
