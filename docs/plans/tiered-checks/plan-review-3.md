## Unnamed risks
- The plan is "done" while the user still waits minutes per turn, because the installed plugin is the old version. Likelihood: high. Mitigation: finding 1.
- A false red from a `check-fast` timeout under load (ollama or the NPU busy) makes the agent "fix" healthy code or loop once per turn. Likelihood: medium when a lib file changes. Mitigation: finding 2.
- NOTCH's `fmt-check` blocks every turn while QML is mid-edit and unformatted. Today `AGENTS.md:32` only asks for `make fmt` before a commit. The agent will start running `make fmt` between turns. Likelihood: medium, impact low. Mitigation: state in the NOTCH `AGENTS.md` that the hook checks formatting, and that `make fmt` is the fix.
- `pair` regression rounds, now likelier because the full suite runs only at the end, meet a verifier that does not know them. The result is a NEEDS DECISION that stalls the story. Likelihood: medium. Mitigation: finding 5.
- The cost of the full suite moves to high-risk story ends: 3-5 runs of 3-5 min each, and every MUST story in this plan is high risk. Likelihood: high, impact time only. Mitigation: finding 6.

## Questions for the user (max 5)
1. When `check-fast` hits its 60 s timeout, should the hook block the turn as it does today, or only report it as a systemMessage? Why it matters: a timeout is not a code failure, and blocking makes the agent "fix" healthy code. Recommendation: keep blocking only after shellcheck runs in parallel and the full-lint case is measured well under 60 s; otherwise report without blocking.
2. NOTCH has two unmerged non-story branches (`feat/27-wallpaper-foundation`, `feat/34-quick-wallpaper`). Before trusting it, should they get `main` merged in, be deleted, or be accepted as falling back to the full suite? Why it matters: checking either one out runs the keyboard-grabbing full suite between turns. Recommendation: delete them if they are abandoned; otherwise merge `main` into them in the NOTCH story.
3. In a high-risk `pair` story, may the verifier's own `Test command:` run count as the final full run when nothing changed after it? Why it matters: it saves one 3-5 min run per story. Recommendation: yes; rerun only when code or tests changed since the last green run.
