# Plan review: tiered-checks
Verdict: PASS WITH CHANGES
Summary: The core idea holds up. The hook prefers `check-fast`, the cache is keyed per target, and `make check` stays the fallback. Every code citation in the plan matches the repo, and the MUST work fits with no deadline. Several gaps need fixing before handoff. ## Unnamed risks
- The full suite runs fewer times, so the Bash tool's 2 to 10 minute ceiling becomes the only limit. With a bench change, `make check` took 319–325 s (idea 27), above the default tool timeout. Likelihood: medium. Mitigation: `pair` step 6 and `ship` step 1 say to run `make check` with a 600 s timeout or in the background.
- Committed but unlinted shell. `pair` commits during the turn, and the hook only lints the dirty tree vs `HEAD`, so committed scripts skip shellcheck until the final check. Likelihood: high, though the impact is low. Mitigation: accepted by gap 6. State it in the docs so nobody reads a green hook as "linted".
- Pair evals cost quota and are nondeterministic (3 runs per case, `--max-cost-usd 6`). Likelihood: medium. Mitigation: budget the eval runs in the story and accept the structural bash tests as the gate.
- A changed hook message breaks downstream parsers. The agy adapter test asserts `startswith("make check failed")`. Likelihood: low. Mitigation: keep the exact wording on the fallback path; add one agy test for `check-fast`.
- Two parallel sessions in one repo, one in `pair` and one ad hoc, may each assume the other ran the suite. Likelihood: low. Mitigation: none needed beyond `ship` always running `make check`.

## Questions for the user (max 5)
1. Should `NOTCH` be trusted for `require-check` now (`git config require-check.trusted true`), or only after the reinstall? Why it matters: until it is trusted, the `NOTCH` `check-fast` story changes nothing. Recommendation: trust it now, and keep the story as the last MUST.
2. When the final full check in `pair` is red, do you want each regression fixed as a new red-to-green step on the same branch, or should `pair` stop and hand it to you? Why it matters: this is the main cost of the new loop, and the plan says nothing about it. Recommendation: a new step per regression; a second failure stops.
3. `delegate-local` is parked. Should its change stay MUST, and should the worker get a retry with the failure tail, or does Claude just verify? Why it matters: no retry exists today, and narrowing the verification undoes a measured safeguard. Recommendation: move it to SHOULD and keep the full `Test command:` after applying the diff.
4. Should OpenCode's generated "run `make check` before done" rule switch to `check-fast`? Why it matters: otherwise OpenCode keeps paying 93–300 s per turn. Recommendation: switch it, and allow `make check-fast` in its permissions.

Recommendations I resolved myself (technical): test the timeout path with a stub `timeout` on `PATH`; reuse the `-f` filter in `check-shell.sh` for changed files and fall back to all files when there is no `HEAD`; keep the fallback message wording unchanged for the agy adapter; regenerate the goldens in each skill story.
