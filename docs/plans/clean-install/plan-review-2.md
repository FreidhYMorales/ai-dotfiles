## Unnamed risks
- A green VM pass goes stale before the format: `quickshell-git`, the AUR packages and `pacman -Sy` at bootstrap.sh:55 float. Review 1 named this, but plan.md:4 sets no freshness rule — medium — Re-run if the pass is older than about 7 days or if `SYS` or the pin changed. Replace `-Sy` with `-Syu`.
- There is no real-hardware test before the wipe, since the image was rejected and the VM has no Wi-Fi, Arc or NPU — medium — Boot the ISO on the laptop and connect to Wi-Fi before emptying `~/Files`. This takes minutes and is independent of the rejected image.
- The external disk is a single point of failure after the format — low to medium — Keep a second copy of coursework and keys until first-boot checks pass.
- A VM failure may be caused by Hyprland on virtio-gpu rather than by the install — medium — Time-box the graphics setup, and record a virgl smoke test before the full pass.
- Stage 4 fixes land on already-public repos, so a mistake there is published immediately — low — Run `gitleaks` and a by-eye diff on every fix through the first-boot checks, not only until the flip.

## Questions for the user (max 5)
1. Is the historical RDP password used anywhere today, and may `backup/` be removed from `SYS` history? — This decides rotation and the rewrite before an irreversible flip. — Recommendation: rotate it regardless and remove all of `backup/`.
2. Do you accept your Gmail address being public on more than 1,300 commits? — It cannot be recalled after the flip, and a rewrite is the only way to change it. — Recommendation: accept it if it is already public on your other repos. Otherwise rewrite `SYS`, `AI` and `NOTCH` before the flip, and update the `SYS` pin afterwards.
3. Will the base install use LUKS? — Bootstrap's GRUB line can make an encrypted install unbootable. — Recommendation: decide now. If yes, change bootstrap and test it in the VM.
4. Keep or drop `secrets.zsh`, `~/.claude/projects` and `worker-bench`, and does `~/Files` return as a real path? — None of this comes back from a clone, and later paths depend on it. — Recommendation: keep all three and keep `~/Files` as a real path.
5. Where exactly are the restic password copy and the `age` passphrase, and can you open them from your phone alone? — Off-site recovery and the keys depend on them. — Recommendation: keep them in a password manager and prove access before stage 3.

Technical recommendations I resolved myself: use `tar` or re-clone for the repos, create the `.local` directories before stowing, set `KEEP_ZSHRC=yes`, and require the `@{u}` check after the final backup.
