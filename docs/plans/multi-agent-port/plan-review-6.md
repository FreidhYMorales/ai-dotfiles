## Unnamed risks
- **The fallback scenario cannot produce skill-story evidence.** Pair step 7 needs a `make eval` result for skill stories, and `make eval` runs `claude plugin eval`. When the Claude quota is out (the whole reason to use OpenCode or agy), skill stories cannot close as written. — Medium — Add a generated pair line for targets: "eval pending (needs Claude)", recorded in the story log and run later.
- **The leftover gentle-ai `sdd-*` skills in `~/.gemini/skills/` remain discoverable in agy** and compete with the flow workflow. Pair already tells the agent to ignore `sdd/*` topics, which shows this is a known trap. — Medium — Cover them with the same move-aside as F1, or list them in `docs/multi-agent.md`.
- **The absolute repo path (with a space) is baked into every generated file.** If the repo moves or is re-cloned elsewhere, every target breaks until `install.sh` runs again. — Low — Add one line to the `install.sh` header and docs. The existing `GEN_REPO_PATH` already covers the tests.
- **OpenCode only sees new generated skill names after a restart.** An `ai-update` during a session leaves the old skill set loaded. — Low — `ai-update` should print "restart OpenCode" when the build changed.
- **The pinned-version warning (1.4.9) fires after every agy auto-upgrade, and the sentinel re-run needs agy quota.** The warning becomes noise. — Low — Have the warning name the exact re-run command, and bump the pin in the same commit as the re-run.
