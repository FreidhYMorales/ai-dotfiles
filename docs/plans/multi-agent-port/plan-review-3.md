## Unnamed risks
- **Claude regressions from the hooks refactor.** Splitting the 6 hooks into cores plus adapters touches the Claude baseline that the plan calls "unchanged". `make mutate` and the hook tests address hooks by their current paths. Likelihood: medium. Mitigation: keep the current hook files as the Claude entry points (core plus Claude adapter in place), and keep every existing hook test passing unchanged.
- **The agy Stop gate traps the user.** Without the `terminationReason` and reentry rules (finding 6), a red tree plus Ctrl-C in agy re-enters the loop and burns quota. Likelihood: medium. Mitigation: finding 6's golden tests run before the smoke.
- **Live agent configs point into a gitignored dir.** If the generator does `rm -rf build/agents` before writing, or someone runs `git clean -fdx`, both agents lose rules and skills until the next install. Likelihood: medium. Mitigation: generate into a temp dir and swap atomically (reuse the `mv --exchange` pattern already relied on in CI). Have `install.sh` warn about dangling links.
- **Two agy `mcp_config.json` files.** Both `~/.gemini/config/mcp_config.json` and `~/.gemini/antigravity-cli/mcp_config.json` exist, and `docs/multi-agent.md` line 26 names the second one. Verifying the wrong file passes while subagents have no engram. Likelihood: medium. Mitigation: item 2 verifies with `agy mcp list` only, and fixes the doc line.
- **CI cost.** Adding generator golden tests and an OpenCode TS type-check could push the 10-minute CI timeout. Likelihood: low. Mitigation: keep the golden tests in pure bash/jq, and run any TS check only if node is present (it is in CI).

Technical recommendations I resolved myself:
- Keep the Claude-side cores fail-open, as already pinned; put fail-closed only in the non-Claude PreToolUse adapters.
- In agy, act on Stop only for `NO_TOOL_CALL`, and treat `executionNum > 1` as `stop_hook_active`.
- Carry hook timeouts into the agy config (330 s for `require-check`).
- Add `source` and a context/message split to the hook contract.
- `make check` compares generated output with committed golden fixtures; a stale installed build dir is only an install-time warning.
- Use one name map: `flow:x` → `flow-x`, `toolkit:x` → `toolkit-x`.
- Swap the build dir atomically.
